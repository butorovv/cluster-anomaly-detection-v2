# UX-0. База визуальной приёмки V2

Исходная версия `20268d208337b4c1f75aa5e80bff7195b913138a`, ветка `feature/qt-gui`. Ноутбук и ВМ сверены, обе рабочие копии были чистыми. В репозитории не было каталога `gui/design-reference`. Для приёмки используются присланные `index.html`, `UX_SPEC.md` и PNG из комплекта V2.

HTML задаёт палитру, размеры, расположение и переходы. В JavaScript отдельно хранятся контексты запуска, вид просмотра, выбранная вкладка, группа, отметка и критерий. Шапка и шкала остаются над изменяемым прокручиваемым содержимым. Данные, имитированные запуски и CSV из JavaScript служат примерами внешнего вида.

Сохраняются Poller, MonitorStore, обе табличные модели, ScoreChart и формы подключения. Обзор, диагностика и журнал получают одну общую оболочку. Для контрольной точки уже принятые запуски читаются из действительных файлов demo.json и verification.json на ВМ, данные выборок — из Master. Это набор для приёмки, постоянный каталог будет следующим согласуемым этапом. Достоверность завершения берётся из отчёта сверки, а не из оформления макета.

Raw хранит оценки и пороги R/B на уровне группы. Временные состояния и активные голоса поступают из RBI2TemporalResult. Локальные узловые оценки IF и признаки вне группы относятся к I2; они не являются отдельным голосом. Evidence содержит ссылки на тики свидетельств. Подробности и идентификаторы помещаются в закрытые блоки.

Текущий demo.ps1 предоставляет Init, Replay, Verify и Stop. Init пишет метаданные запуска и поднимает Master с loopback. Stop останавливает контейнеры с сохранением томов. Для истории потребуется отдельно проверить безопасное чтение сохранённой БД, не поднимая отдельный Master для каждого запуска постоянно. Интеграция QProcess, постоянный каталог и CSV ждут согласования UX-1/UX-2.

Сборка, запуск и проверки только на ВМ. VNC :11 и Master сохранённого D2 слушают loopback. Заново запускать D2 для сравнения интерфейсов не требуется.
